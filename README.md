# SubPanel

运行在 Cloudflare Workers 上的轻量级 Mihomo（Clash Meta）订阅管理面板。把订阅、手动节点和自己的模板组合成配置，再交给客户端使用。

AI coding.

## 描述

- 管理订阅和手动节点，保存最多 5 份输出配置，每份都有独立订阅链接。
- 订阅支持两种方式：1、**Provider 托管**由客户端拉取；2、**节点列表**由面板解析后写入配置，支持从链接获取、上传文件或粘贴内容。
- 模板可粘贴 YAML，也可填写远程 URL；支持附加规则、静态 Hosts 和 Hosts 订阅。
- 提供登录、修改密码、重置订阅 Token，以及备份导入/导出。

这是配置管理工具，不是代理服务，也不提供节点。

## 部署

1. 在 Cloudflare 创建 Worker 和 KV 命名空间，把 KV 绑定到 Worker，**变量名必须是 `SUBPANEL_KV`**。
2. 将项目根目录的 **`main.js` 整份复制**到 Worker 编辑器，保存并部署。仅部署不需要 Node.js 或安装依赖。
3. 打开 Worker 的 HTTPS 地址。`workers.dev` 无法正常访问时，可绑定自己的域名。
4. 首次用密码 **`admin`** 登录，立即到设置中修改密码。
5. 推荐添加 Cron 触发器 **`0 * * * *`**，让 Worker 每小时检查 Hosts 是否到期。不配置也能用，但自动检查要等打开面板或客户端拉取配置时才触发。

不要更换或删除原 KV 绑定，数据都存在里面。升级前建议先导出备份。

## 开始使用

1. **添加模板**：新安装没有内置默认模板，需要自行添加。
2. **添加订阅或节点**：节点列表模式要先获取、上传或粘贴节点内容。
3. **编辑输出配置**：选择模板和节点来源，按需开启规则、Hosts 附加，然后点击“合成更新”。
4. **复制订阅链接**到客户端，格式为 `https://你的域名/config=<token>`，请直接使用面板给出的完整链接。

修改来源、模板、规则或静态 Hosts 后，通常需要重新“合成更新”。保存规则草稿不等于更新客户端配置。

### 模板怎么写

模板必须包含 `proxy-groups` 和 `rules` 数组。面板会加入所选节点和 Provider，**不会替你改写策略组来引用它们**。最简单可以用：

```yaml
mixed-port: 7890
mode: rule
proxy-groups:
  - name: 节点选择
    type: select
    include-all: true
rules:
  - MATCH,节点选择
```

这个示例只用于跑通流程，不包含分流规则。也可以使用自己的完整模板；已有 `proxies`、`proxy-providers` 会合并，但 Provider 名称不能与面板订阅同名。需要面板插入内容的区块，请使用上例那样的多行写法，避免行内写法无法合并。

## 更新与数量限制

- 订阅、手动节点、模板、输出配置、Hosts 订阅：各最多 **5 个**。
- 节点列表输入：UTF-8 的 `.yaml`、`.yml`、`.txt`，单次最多 **2 MiB / 5,000 个节点**，解析结果最多 4 MiB。
- 附加规则：最多 **500 条**；Hosts：每个订阅源和静态内容各最多 **300 个域名**。
- Provider 开启自动更新后，由客户端每小时拉取；节点列表模式需要手动更新。
- Hosts 开启自动更新后，满 **24 小时**才重新抓取；失败后有 **15 分钟**冷却。多个输出配置会分批重建，可能不是同时更新。

Cloudflare 的免费额度和 CPU 限制仍然适用，大型模板或大量节点需要留意 Worker 日志与用量。

## 备份与安全

- 备份包含订阅链接、节点凭据和配置 Token，**请当作密码文件保管**。订阅链接本身也相当于访问凭证，Token 不是内容加密。
- 备份不含管理员密码和已生成的 YAML。导入后需要重新合成；旧备份缺少节点缓存时，还需要重新获取、上传或粘贴节点。
- 链接泄露后可重置 Token，并在客户端更换链接。KV 更新可能需要一点传播时间。
- 忘记密码时，可在绑定的 KV 中修改 `ADMIN_PASSWORD`，然后重新登录。
